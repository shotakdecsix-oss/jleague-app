# 第9弾 実装指示：全体ビュー（J1/J2/J3 横断）

対象リポジトリ: `jleague-app`
前提ドキュメント: `docs/handoff-jleague-dashboard.md`、`docs/prompt-jleague-impl-8.md`

現在のアプリは「自クラブ中心」の作りになっている。これを壊さずに、**J1〜J3を横断して眺めるモード**を追加する。

---

## 全体の不変条件（既存方針。破らないこと）

- 日付・時刻は `kickoffJst`（`strTimestamp` 由来）のみ使う。`dateEvent` / `dateEventLocal` / `strTimeLocal` は参照しない。
- 順位付けは `scripts/standings.py` の `rank_teams()` を通したもの（＝`{league}_standings.json`）のみ使う。フロントで順位を計算し直さない。
- **`playedDiff`（消化試合数の差）は順位を表示するあらゆる画面で省略しない。** 全体ビューでも同じ。
- Jリーグ公式由来のデータ（`club_extra.json`、`data/tmp/`）は配信対象に含めない。本指示で扱うのは TheSportsDB 由来＋自前マスタのみ。
- 新規ファイルは最初から Write ツールで作る（bash の `cp`/`touch` で作ったファイルは後から編集できなくなる既知の問題がある）。
- 出力ファイルを増やしたら `scripts/build_dist.py` に反映する。

---

## 0. 全体構成

**ヘッダにモード切替を置く。** タブバーの構成そのものをモードで差し替える。

```
┌────────────────────────────┐
│  [ クラブ ] [ 全体 ]   ← モード切替（ヘッダ）  │
├────────────────────────────┤
│                            │
│         コンテンツ          │
│                            │
├────────────────────────────┤
│ クラブモード: ホーム/日程/順位/スタッツ/選手/ニュース │
│ 全体モード:   日程 / 順位 / 予想                │
└────────────────────────────┘
```

- クラブモードの既存6タブは**一切変更しない**。
- 全体モードのタブは `日程 / 順位 / 予想` の3つ。
- モードは `state.viewMode`（`"club"` / `"all"`）で持つ。
- **ハッシュルーティングにモードを含める**（例: `#all/schedule`、`#club/home`）。既存の `currentTabFromHash()` / `setActiveTab()` を拡張する。リロードやブラウザバックでモードごと復帰できること。
- モードは `localStorage` に保存し、次回起動時に復元する（既存の `loadFav()` / `saveFav()` と同じ流儀）。

### テーマ色の扱い（見落としやすい）

現在 `applyTheme(team)` がクラブ色を CSS 変数に流し込んでいる。**全体モードでは中立配色に切り替える。** 特定クラブの色で3リーグ全体を塗ると、どのリーグを見ているのか分からなくなる。

- `applyTheme(null)` で中立パレットを適用できるようにする。
- 中立モードでも自クラブの行・試合だけはクラブ色でハイライトする（後述）。
- モードを戻したらクラブ色テーマも復帰すること。

---

## 1. 全体ビュー用データファイルの生成

3リーグの `{league}_matches.json` をフロントで3つ読む実装にしてはいけない。合計 660KB あり、日付軸に混ぜるために全件パースすることになる。

新規スクリプト `scripts/build_calendar.py` で、**日付軸ビュー専用の軽量ファイルを1つ**生成する。

```
data/processed/calendar.json
```

構造（キーは短縮する。1140試合で raw 約160KB、gzip 後 約12KB。Render は gzip 配信なので実用上まったく問題にならない）:

```json
{
  "meta": {
    "season": "2026-2027",
    "generatedAtJst": "2026-08-20T22:49:39+09:00",
    "leagues": ["j1", "j2", "j3"],
    "counts": { "j1": 380, "j2": 380, "j3": 380 }
  },
  "matches": [
    {
      "e": "2551707",
      "l": "j2",
      "r": 1,
      "k": "2026-08-08T14:45:00+09:00",
      "b": false,
      "s": "FT",
      "h": ["137706", "札幌", 2],
      "a": ["139898", "徳島", 0]
    }
  ]
}
```

- `h` / `a` は `[idTeam, short, score]`。未消化は score が `null`。
- `b` は `kickoffTbd`。
- **生成時に `k` の昇順（同時刻は j1→j2→j3）でソート済みにしておく。** フロントでソートさせない。
- `kickoffJst` が `null` の試合（日程未定）は配列の末尾にまとめ、`k: null` のまま出す。フロントは「日程未定」セクションに置く。
- `json.dumps(..., separators=(',',':'))` で出力する（この1ファイルだけは indent なし。可読性より転送量を優先）。
- `update_all.py` の手順に `build_calendar` を追加する。実行位置は `fetch_batch` の後、`build_dist` の前ならどこでもよい。

順位と予想順位は既存の `{league}_standings.json`（7KB）と `{league}_simulation.json`（17KB）をそのまま使う。3リーグ合わせても72KBなので、集約ファイルは作らない。**追加のバッチ処理は `calendar.json` の生成だけ。**

## 2. 全体モード「日程」タブ

### 2-1. 基本の見せ方：日付軸で3リーグ混在

節ではなく**日付**でグルーピングする。1つの日付ブロックの中はキックオフ時刻順で、リーグを混ぜて並べる。行頭にリーグバッジを置く。

```
── 8/22(土) ────────────────
 [J2] 14:00  藤枝  1 - 0  山形     ○
 [J1] 14:00  町田  2 - 2  広島
 [J3] 15:00  鳥取  - vs -  讃岐
 [J2] 19:00  湘南  vs      千葉   ★
── 8/23(日) ────────────────
 ...
```

- 「今日どこがやっているか」が一目で分かることがこのタブの目的。**節番号での並べ替えは提供しない**（節と日程は延期でずれるため、節単位で見たいときはクラブモードの日程タブがある）。
- 節番号は各行の隅に小さく出す程度でよい（`第3節`）。
- リーグバッジは J1/J2/J3 で色分けする。**クラブ色ではなくリーグ色**（中立の3色）を使う。
- 自クラブが絡む試合は行を強調する（背景・左罫にクラブ色）。上例の ★ の行。
- 終了した試合はスコアを、未消化はキックオフ時刻を出す。`b: true`（時刻未定）の試合はその日付ブロックの末尾にまとめ、「時刻未定」と表示する。
- 試合行をタップしたら、そのクラブのクラブビューへ飛べるとよい（任意）。

### 2-2. 初期スクロール位置（必須）

**タブを開いたら「今日」の位置から表示する。** これが無いと 1140 試合の先頭（開幕節）が表示されて毎回スクロールする羽目になる。

- 今日に試合が無ければ、**今日以降で最も近い試合日**を先頭にする。
- シーズン終了後は最終節を表示する。

### 2-3. 描画量の制御（必須）

1140試合を一度に DOM 化しない。スマホで確実に重くなる。

- 初期描画は**基準日の前後14日ぶん**のみ。
- 上下端に「さらに前を見る」「さらに先を見る」ボタンを置き、押すたびに14日ぶん追加描画する。
- 仮想スクロールのような凝った実装は不要。この方式で十分。

### 2-4. リーグフィルタ

日付ブロックの上に `J1 / J2 / J3` のトグルチップを置く。オフにしたリーグは非表示。選択状態は `localStorage` に保存する。3リーグ全部オンだと1日20試合を超える日があり、絞りたい需要が確実にある。

## 3. 全体モード「順位」タブ

- 上部に `J1 / J2 / J3` のセグメント切替。**既定は自クラブの所属リーグ。**
- 中身は既存のクラブモード順位タブの表示ロジックを流用してよいが、テーマ色は中立、自クラブ行のみハイライト。
- **`playedDiff` を必ず出す。** 同順位クラスタ（`tiedWith` が空でない行）の見せ方も既存踏襲。
- 昇格・降格圏の色帯は `promotionRules` から動的に引く。ハードコードしない（3リーグでルールが違う。次章の注意点を参照）。

---

## 4. 全体モード「予想」タブ ― B案（帯＋タップで詳細）

**採用する見せ方は「P10〜P90の帯を並べ、行をタップすると詳細が開く」形式。**

### 4-1. データ

`{league}_simulation.json` に必要な値は**すべて既に入っている**。バッチ側の変更は不要。

| 用途 | フィールド |
|---|---|
| 並び順 | `expectedRank`（昇順） |
| 帯の左端・右端 | `rankP10` / `rankP90` |
| 帯の中の縦線 | `medianRank` |
| 帯の上の丸印 | `currentRank` |
| 右端の数値 | `expectedPoints` |
| 詳細（展開時） | `modeRank` / `modeRankProb` / `champion` / `autoPromotion` / `playoff` / `relegation` |

### 4-2. 一覧の描画

```
      ┌ 1位            10位           20位 ┐
 1 藤枝 [███████░░░░░░░░░░░░░]  66
 2 横浜FC[███████░░░░░░░░░░░░]  65
 3 湘南 [█████████░░░░░░░░░░░]  62   ← 自クラブ強調
 ...
```

- 横軸は 1位〜20位に固定。左が1位。
- 帯は `rankP10` 〜 `rankP90`。`left = (P10-1)/20*100 %`、`width = (P90-P10+1)/20*100 %`。
- 帯の塗りはクラブ色（マスタの `color`）。
- 帯の上に `medianRank` の位置へ白い細い縦線、`currentRank` の位置へ白縁の丸印を重ねる。「今ここ / 予想はこの範囲」が1行で読める。
- 行の左に通し番号（`expectedRank` 順の並び順であって、予想順位そのものではない）、右に `expectedPoints` を整数で。
- 背景にゾーンの色帯（昇格圏・PO圏・降格圏）を薄く敷く。

**色の落とし穴**: クラブ色には `#000e32`（栃木C）や `#10234f`（徳島）のように暗い背景色と同化するものがある。既存の `luminance()` / `mixWhite()` ヘルパーを使い、**輝度が閾値を下回る色は自動で持ち上げる**か、帯に 1px の明るいインセット境界を必ず入れること。どちらか片方では足りない場合は両方やる。

### 4-3. ゾーン帯はリーグごとに違う（重要）

`promotionRules` をマスタから読んで動的に描く。**ハードコード厳禁。**

| リーグ | champion | autoPromotion | playoff | relegation |
|---|---|---|---|---|
| J1 | [1] | なし | なし | [18,19,20] |
| J2 | [1] | [1,2] | [3,4,5,6] | [18,19,20] |
| J3 | [1] | [1,2] | [3,4,5,6] | **`null`** |

**J3 の `relegation` は意図的に `null` にしてある。** マスタの `note` にある通り、2026年移行期のJFLとの昇降格について情報が食い違っているため未確定という判断。`relegationUnverified` という別キーに候補値が入っているが、**これを画面に出してはいけない。** `relegation` が `null` のリーグでは降格圏の帯・凡例・詳細の降格確率を丸ごと出さないこと。

同様に J1 には `autoPromotion` / `playoff` が存在しない。キーの存在チェックを必ず入れる。

### 4-4. タップで開く詳細

行をタップするとその行の下にアコーディオンで展開する。

```
最もあり得る順位  3位  （その確率 12.7%）
優勝 11.1%  ／  自動昇格 22.9%  ／  PO圏 44.6%  ／  降格 0.2%
```

- **`modeRankProb` を必ず併記する。** これは `add-projected-table-rev2.md` で確立した方針。順位だけ大きく出すと「3位で決まり」に見えるが、実際は「20通りのうち3位が最多なだけ」で確率は12.7%しかない。確率を添えることでその頼りなさがそのまま伝わる。
- 表示するゾーン確率は `promotionRules` に存在するものだけ（4-3参照）。
- 同時に開くのは1行だけ（他を開いたら閉じる）。
- 初期状態で自クラブの行だけ開いておく。

### 4-5. 注記（必須）

一覧の下に常時表示する。

> ※ 帯は10000回のシミュレーションのうち中央8割が収まる順位の範囲です。
> ※ 開幕直後はモデルがリーグ平均に寄るため、確率の動きは実力変化を意味しません。

2つ目は第8弾の推移グラフと同じ理由（縮約 K=6）。全体ビューでも同じ誤読が起きるので省略しない。

### 4-6. リーグ切替

順位タブと同じく `J1 / J2 / J3` のセグメント。既定は自クラブの所属リーグ。60行を一度に出さない。

## 5. データロード

既存の `ensureXxx(league)` パターンに合わせる。

- `ensureCalendar()` — `calendar.json` を取得。全体モードの日程タブを最初に開いたときだけ。
- 順位・予想タブは、そのとき選択中のリーグの `{league}_standings.json` / `{league}_simulation.json` のみ取得する。**3リーグ分をまとめて先読みしない**（セグメントを切り替えたときに初めて取りに行く）。
- 既存の `state.cache[league]` にそのまま乗せれば、クラブモードと共有されてダブルフェッチを防げる。
- 取得失敗時はタブごとにエラー表示して、アプリ全体は落とさない（既存の `getJsonOptional` の流儀）。

---

## 6. build_dist への反映

`calendar.json` は `data/processed/` 配下なので、既存の `COPY_DIRS` でそのままコピーされる。**追加設定は不要**だが、生成されていることを `build_dist.py` の実行時に確認するチェックを入れておくとよい（無ければ warn を出す）。

---

## テスト（必須）

**バッチ（`scripts/test_build_calendar.py`）**
- 出力の `matches` が `k` の昇順にソートされていること。同時刻は j1→j2→j3 の順であること。
- `k` が `null` の試合が配列末尾にまとまっていること。
- 3リーグの試合数の合計が `meta.counts` の合計と一致すること。
- 未消化試合の score が `null` で出ること（`0` にフォールバックしていないこと）。

**フロント（手動確認でよいが必ず全部通すこと）**
- 全体モードの日程タブを開いた初期スクロール位置が「今日、または今日以降で最も近い試合日」であること。今日に試合が無い日でも正しく動くこと。
- 「さらに前／先を見る」で日付が正しく伸び、重複描画されないこと。
- リーグフィルタを全部オフにしたときに空状態のメッセージが出て、例外にならないこと。
- **J3 の予想タブに降格圏が一切表示されないこと**（帯・凡例・詳細の降格確率すべて）。
- **J1 の予想タブに自動昇格圏・PO圏が表示されないこと。**
- 暗いクラブ色（栃木C `#000e32`、徳島 `#10234f`、大宮 `#00164b`）の帯が背景と同化せず視認できること。
- モードを切り替えたときにテーマ色が中立⇔クラブ色で正しく切り替わること。
- `#all/standings` を直接開いてリロードしても全体モードの順位タブが復元されること。
- クラブモードの既存6タブの表示・挙動が一切変わっていないこと（リグレッション確認）。

---

## 実装順の推奨

1. `build_calendar.py` とそのテスト（フロント無しで完結）
2. モード切替の骨組み（ヘッダ、タブバー差し替え、ハッシュ、テーマ中立化）— 中身は空でよい
3. 全体モード「順位」タブ（既存ロジックの流用が効くので最も軽い）
4. 全体モード「予想」タブ（B案の帯）
5. 全体モード「日程」タブ（初期スクロールと段階描画があるので最後）

各ステップごとに `python scripts/update_all.py` が最後まで通ることを確認してから次へ進むこと。
