# 修正指示：オンデマンド更新（改訂2・更新ボタンの置き場所）

`prompt-jleague-impl-10.md` の **「6. UI」を破棄します。** 本ファイルで置き換えてください。
1〜5章および7〜8章はそのまま有効です。

---

## 破棄する理由

元の指示では更新ボタンを「ホームタブの上部」と「全体ビューの日程タブの上部」に置くとしていました。これは**ボタンのスコープを誤認させます。**

ホームタブは選択中クラブの画面なので、そこに「更新」があると **選択中のクラブについてだけ更新されるように見えます。** 実際にはこの機能は J1・J2・J3 の3リーグ分をまとめて取得します。見た目と実際の挙動が食い違っている状態です。

加えて、2箇所にボタンがあると「それぞれ別の更新」に見えます。

## 全リーグ更新のままでよい理由（確認）

スコープを「選択中クラブのリーグだけ」に狭める案は採用しません。

- 全体ビュー（第9弾）がある以上、1リーグだけ更新すると**全体ビューが不整合になる**。
- コスト差が小さい。1リーグなら最大2リクエスト、3リーグでも最大6リクエスト。数秒の差でしかない。

**挙動は全リーグのまま、置き場所と見せ方でスコープを正しく伝える**方針にします。

## 1. ヘッダを2段に整理する

現在のヘッダは以下の4要素がフラットに並んでいます。

```html
<header>
  <h1>Jリーグ ダッシュボード</h1>
  <div id="deployBadge"></div>
  <div id="modeToggle">クラブ / 全体</div>
  <select id="clubSelect"></select>
</header>
```

これを**役割で2段に分けます。**

```
┌──────────────────────────────────┐
│ Jリーグ ダッシュボード      ⟳ 21:30   c0186e7 │  ← 上段：アプリ全体・データの状態
│ [ クラブ | 全体 ]        [ 湘南ベルマーレ ▼ ] │  ← 下段：何を見るか
└──────────────────────────────────┘
```

- **上段** = アプリ全体に関わるもの。更新ボタンと `deployBadge` をここに置く。
- **下段** = 表示対象の選択。`modeToggle` と `clubSelect`。

更新ボタンを `clubSelect` から物理的に離し、`deployBadge`（誰が見てもアプリ全体の情報）の隣に置くことで、「クラブ単位の操作ではない」ことが位置で伝わります。

狭い画面では上段の `deployBadge` を省略してもよい（デバッグ用の表示なので優先度が低い）。更新ボタンは常に出すこと。

## 2. ボタンの表記

**「更新」という単語を単体で使わない。** 画面のリロードと区別がつかず、スコープも伝わりません。

- 通常時: `⟳ 21:30`（アイコン＋最終更新時刻のみ。省スペース）
- タップ可能であることは、アイコンとタップ領域（44px以上）で示す
- `aria-label` は **「J1〜J3の最新結果を取得」** とする。読み上げでスコープが伝わるようにする
- ツールチップ（`title`）も同じ文言にする

## 3. スコープは完了メッセージで明示する（最重要）

位置と表記だけでは足りないので、**押した結果でスコープを確定的に伝えます。** ここが一番効きます。

| 状況 | 表示 |
|---|---|
| 取得中 | `J1〜J3 を取得中… 2/6` |
| 完了（更新あり） | `J1〜J3 の最新結果を取得しました（3試合更新）` |
| 完了（更新なし） | `最新でした（更新なし）` |
| 対象試合なし | `いま更新対象の試合がありません` |
| 一部失敗 | `一部のリーグを取得できませんでした（J1・J2 のみ更新）` |
| 全失敗 | `更新できませんでした` |

- トーストまたはヘッダ直下のインラインメッセージで出す。3〜4秒で自動的に消す。
- **「J1〜J3」という文字列を必ず含める。** 1回でも見れば、以降このボタンが全リーグ対象だと分かります。
- 進捗の `2/6` は、数秒の待ちを無反応に見せないために必要。

## 4. 更新時刻の意味を混ぜない

ヘッダに出す `21:30` は「表示中のデータが何時時点か」です。バッチ由来とオンデマンド由来の**新しいほう**を出します。

- バッチのみ: `⟳ 21:30`
- オンデマンドで取得済み: `⟳ 23:14 ●`（暫定であることを示す小さいドットを添える）

ドットの意味は、ヘッダの時刻をタップしたときに開く小さなポップオーバーで説明します。

```
データの基準
　試合結果   23:14（アプリから取得・暫定）
　順位       23:14（暫定・当該チーム間比較なし）
　昇格確率   8/21 21:30（次回のバッチで更新）
　ニュース   8/21 21:30
```

第10弾4章で「確率の表示箇所に基準時刻を併記する」としたものは、**このポップオーバーに集約してよい**（各所に日時を散らすとうるさくなるため）。ただし**ホームタブの昇格確率タイルだけは、その場に小さく `8/21 21:30時点` を残すこと。** 一番誤解されやすい数字なので、ここだけはポップオーバーを開かせない。

## 5. 各画面での暫定表示（元の指示から変更なし）

- 更新された試合のスコアに小さいドット、または行に淡い背景
- 順位表のヘッダに「暫定」バッジ
- pull-to-refresh は実装しない（スクロールで誤爆するため）
- 最短60秒のクールダウン。クールダウン中はボタンを無効化し、残り秒数を出す

第10弾6章の注記はそのまま維持します。ヘッダのポップオーバー内に置いてください。
