# 修正指示：日程タブの勝敗表示 ／ リーグ別の昇降格ラベル

`data/masters/*.json` の `promotionRules` は更新済みです。**マスタ側の作業は不要です。**

---

## 1. 日程タブで、自クラブの勝敗が一目で分かるようにする

いまは消化済み試合がスコアだけで、**自クラブが勝ったのか負けたのかが読み取れません。**
「直近の結果」タブと同じ表現に揃えてください。

- 自クラブが絡む消化済みの試合に、**W / D / L のピル**を付ける（既存の `.pill` クラスをそのまま使う）
- 判定は**自クラブ視点**。ホームかアウェイかで反転させること
- スコアは**自クラブ側を先に**表示する（`2 - 1` の左が常に自クラブ）か、それが難しければ
  自クラブ側のスコアだけ太字にする。**どちらが自分の点なのか分からない状態にしないこと**
- 「リーグ全体」トグルのときは、**自クラブが絡む行だけ**W/D/Lを付ける。他クラブ同士の試合には付けない
- 自クラブが絡む行は、順位表と同じように背景を淡く色付けして目立たせる（`--me-bg` が既にあります）

## 2. リーグごとに昇降格のラベルを変える

**J1で「昇格確率」と出ています。J1に昇格はありません。争点は優勝と残留です。**

`promotionRules` の構造を変えました。**キーの有無で、そのリーグに何の区分があるかを判定してください。**
リーグ名で条件分岐しないこと（将来リーグが変わっても壊れないようにするためです）。

```json
"promotionRules": {
  "champion": [1],
  "autoPromotion": [1, 2],
  "playoff": [3, 4, 5, 6],
  "relegation": [18, 19, 20],
  "labels": { "champion": "優勝", "autoPromotion": "自動昇格",
              "playoff": "昇格プレーオフ", "relegation": "降格" },
  "totalRounds": 38
}
```

- **表示するラベルは `labels` から取る。**コード側に「昇格」「優勝」の文字列を持たない
- **値が `null` または キーが無い区分は、確率タイルも順位表の色帯も出さない**
- セクションの見出しも切り替える。`autoPromotion` が無いリーグ（J1）は
  **「昇格確率（シミュレーション）」ではなく「優勝・残留確率（シミュレーション）」**にする

### リーグごとの結果

| | 出すタイル |
|---|---|
| **J1** | 優勝 ／ 降格 の2つ |
| **J2** | 自動昇格 ／ 昇格プレーオフ ／ 降格 の3つ |
| **J3** | 自動昇格 ／ 昇格プレーオフ の2つ（降格は後述の理由で出さない） |

`simulate.py` 側も、`autoPromotion` 決め打ちをやめて `promotionRules` のキーを走査する形にしてください。
出力の `teams[]` には、区分名をそのままキーにした確率を入れる（`champion` / `autoPromotion` /
`playoff` / `relegation`）。**存在しない区分は `null`。**

## 3. **J2の降格圏が間違っていました**

これまでマスタに `relegation: [19, 20]` と入っていましたが、**正しくは18位・19位・20位の3クラブ**です。
修正済みです。順位表の降格圏の色帯と、降格確率の両方に影響します。

## 4. J3の降格は、いまは出しません

調べたところ情報が食い違っていました。「19位がJFLとの入れ替え戦、20位が自動降格」とする記事がある一方で、
**2026年の移行期はJFLとの昇降格を行わない**とする記事もあります。

どちらか確証が取れるまで、J3の `relegation` は `null` にしてあります（候補値は `relegationUnverified` に
退避）。**推測で埋めないでください。**確認できたら値を移すだけで反映されます。
