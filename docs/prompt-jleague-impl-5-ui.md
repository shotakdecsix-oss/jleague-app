# 実装指示：第5弾（UI改修 ＋ スタッツ順位の補完）

対象は `index.html` と `scripts/stats.py`。**データ取得系（`fetch_batch.py` / `fetch_official.py` /
`fetch_news.py` / `simulate.py`）には一切触らないでください。**

前提は従来どおり（Python 3.10 / PowerShell 5.x / 追加ライブラリなし / Writeツールでファイル作成）。
`index.html` は外部ライブラリを使わない単一ファイルのまま維持します。**Chart.js等は入れず、レーダーチャートは
インラインSVGを手で組み立ててください。**

# 1. タブ化（最優先）

いまの1画面スクロールは、順位表20行＋スタッツ＋選手＋ニュースで縦に長くなりすぎています。**下部固定のタブバー**に分割します。

| タブ | 中身 |
|---|---|
| **ホーム** | 次の試合 ／ 直近の結果 ／ 昇格確率（要約3つ＋説明） |
| **順位** | 順位表（現状のまま） |
| **スタッツ** | レーダーチャート ／ 指標一覧（順位つき） |
| **選手** | leaders（今季の主役）／ 選手一覧 ／ 公式リンク |
| **ニュース** | 公式ニュース ／ Google News ／ OB選手 |

- タブバーは画面下に固定（`position:fixed; bottom:0`）。`env(safe-area-inset-bottom)` を必ず考慮すること
- **選択中のタブはクラブカラーで示す**（アイコンは使わずテキストのみで可）
- **現在のタブを `location.hash` に持たせる**（`#standings` など）。リロードしても同じタブに戻ること
- クラブを切り替えてもタブは維持する
- ヘッダー（クラブ選択）は全タブ共通で上部に残す
- **データの読み込みはタブ切替時に遅延させる。** 初回表示ではホームタブに必要なものだけ読む

# 2. 背景をクラブカラーで染める

現状はヘッダーのみクラブカラーで、背景は白に6%混ぜたごく薄い色です。**もっと全体を染めます。**

- マスタの `color`（メイン）と `colorSub`（サブ）に加え、**3色目は `color` を暗くした派生色をコードで生成**する
  （マスタは変更しない）。HSL/OKLabに変換せず、単純に各チャンネルを 0.72 倍する程度でよい
- **ページ背景**：上端に `color`、下端に `colorSub` を置いた**縦方向のグラデーション**。ただし
  どちらも白に 10〜14% 混ぜた薄さにすること（`mixWhite()` が既にある）
- **ヘッダー**：`color` → 3色目（暗い派生色）の横グラデーション。文字色は既存の輝度判定をそのまま使う
- **タブバー**：白基調のまま、選択中のみクラブカラー
- **カード（`.card`）は白のままにしてください。** ここまで染めると順位表の数字が読めなくなります

**判定基準：順位表とスタッツの数字が、染める前と同じだけ読めること。** 読みにくくなったら混色比を下げること。

# 3. チーム名クリックで切り替え

順位表のクラブ名、次の試合の対戦相手、直近の結果の対戦相手 — **これらをクリック/タップでそのクラブの
ダッシュボードに切り替わるようにします。**

- 各要素に `data-idteam="137715"` を持たせ、**イベント委譲**（`document.addEventListener("click", ...)`）で拾う。
  行ごとにリスナーを張らないこと
- 切り替えたら `<select>` の値も同期させる
- 別リーグのクラブでも切り替わること（`findTeam()` がリーグ横断で引ける）
- **タップ可能に見えること。** 下線かシェブロンを添える。色だけで示さない
- 切り替え時は**同じタブのまま**、ページ先頭にスクロールする

# 4. 昇格確率にポアソンシミュレーションの説明を付ける

数字だけ出ていると根拠が分かりません。確率の下に**折りたたみ（`<details>`）**で以下を入れてください。
**文章はこのまま使って構いません。**

> **この確率の出し方**
>
> 消化済みの試合から、クラブごとの攻撃力と守備力、それにホームアドバンテージを推定します。ただしシーズン序盤は
> 試合数が少なく、1試合の結果に引きずられて極端な値になるため、**リーグ平均に強く寄せる補正（縮約）**をかけています。
> 消化6試合で「自チームの実績」と「リーグ平均」がちょうど半々になる強さです。
>
> そのうえで、残っている全試合の得点を**ポアソン分布**（サッカーの得点分布によく当てはまる分布）から
> ランダムに生成し、シーズンを最後まで実行します。これを**10,000回**繰り返し、各クラブが何位で終わったかを
> 数え上げたものが、この確率です。順位の決め方は順位表と同じ関数を使っているので、勝点が並んだときの
> 当該チーム間比較まで再現しています。
>
> **この推定の限界**
>
> - 得点を**独立**に扱っているため、0-0や1-1のような噛み合った試合が実際より少なく出ます
> - 移籍・負傷・出場停止・日程の過密を**一切考慮していません**
> - 消化試合が少ないうちは、ほぼ「リーグ平均からの距離」しか見ていません。**序盤の数字は参考程度に**

- `meta.basedOnMatches` が **10未満のときは、確率の近くに「消化N試合時点の推定」を常時表示**すること
  （折りたたみの中ではなく、外に出す）
- 確率は**小数第1位までのパーセント**で表示（`18.2%`）。小数第3位まで出さないこと

# 5. スタッツのレーダーチャート

## 5-1. 何を描くか

**選択クラブ1つぶんだけ**を描きます。複数クラブの重ね描きはしません（凡例が要るうえ、モバイルでは潰れます）。

軸は**6つに固定**します。多いと読めません。

```
攻撃力      scorePg（公式）        1試合平均得点数
守備力      gaPerGame（自前）      平均失点 ※少ないほど良い
支配率      ballRate（公式）       平均ボール保持率
パス        passCountPg（公式）    1試合平均パス数
運動量      distance（公式）       1試合平均走行距離
勝負強さ    pointsOverX（自前）    期待勝点からの上振れ
```

## 5-2. 値の作り方

**各軸の値そのものではなく、リーグ内順位を正規化した値**を使います。単位の違う指標を1つの図に載せるには
これしかありません。

```
軸の値 = (クラブ数 - 順位) / (クラブ数 - 1)     # 1位 → 1.0（外周）、最下位 → 0.0（中心）
```

「少ないほど良い」指標（平均失点）は**順位が既に昇順で付いている**ので、この式のままで正しく外周に向きます。

## 5-3. 描き方（インラインSVG）

- **6角形のグリッドを3本**（0.25 / 0.5 / 0.75 の位置）＋外周。線は 1px のごく薄いグレー。**破線は使わない**
- **0.5（リーグ中位）のリングだけ少し濃く**して基準線と分かるようにする
- データ多角形：**塗りはクラブカラーの半透明（18%程度）、輪郭は 2px の実線**
- 頂点にマーカーを置く（**直径8px以上**、タップ判定はそれより大きく）
- **各軸に直接ラベルを置く**：軸名と `3位/20`。凡例は作らない（1系列なので不要）
- 数値の文字色は**クラブカラーではなく通常のテキスト色**にすること。色は多角形が担う
- **クラブカラーが明るい場合（既存の `luminance()` が 0.5 超）は、輪郭とマーカーに暗い派生色を使う。**
  柏レイソルの黄色などは、白背景に 2px の線を引いても見えません
- 頂点をタップしたら、その指標の値と順位をツールチップで出す

## 5-4. レーダーチャートの限界を明記する

図の下に小さく次を添えてください。**面積に意味がある図だと誤解されるのが最大の失敗です。**

> 各軸はリーグ内順位を外周（1位）〜中心（最下位）に置き換えたものです。**面積の大小に意味はありません。**
> 軸の並び順によって形が変わるため、クラブ間の比較は形ではなく各軸の順位で行ってください。

- **軸の並び順は全クラブで固定**すること（クラブごとに並べ替えない）
- レーダーの下に**指標一覧の表**を必ず置く。図が読めない環境でも情報が取れるようにするためです

# 6. 「1試合平均パス数」「平均ボール保持率」に自前の順位を付ける（`stats.py`）

現状これらは `club_extra.json` の公式 `rank` をそのまま使っていますが、**自前でも計算して突き合わせてください。**

`club_extra.json` には60クラブ全ての `clubStats` が入っているので、同一リーグのクラブを集めれば
自前で順位を出せます。

- 同一リーグ内で `value` を並べ、**同値は同順位**で順位を付ける（`passCountPg` と `ballRate` は高いほど上位）
- 出力に **`rank`（採用値）／ `rankOfficial` ／ `rankComputed`** の3つを持たせる
- **食い違ったら警告を出す。**`[warn] j2 ballRate: 公式rank=3 自前rank=5（採用: 公式）`
- **採用は公式を優先。** ただし公式 `rank` が欠けているクラブがあれば自前の値で補う
- 他の公式指標（`scorePg` `distance` `sprint` `cleanSheet`）にも同じ照合を入れておくこと。
  **`seasonKey` の解釈が正しいかどうかを確かめる手段にもなります**（違うシーズンの数字が混ざっていれば
  自前順位と大きくずれるはずです）
